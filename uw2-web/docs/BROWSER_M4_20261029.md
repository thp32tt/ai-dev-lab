# 대항해시대 II Browser M3/M4 — Playable town walking and sail-to-sea
Date: 2026-10-29 KST

## Result
The N100 browser runtime is now directly controllable in the user's Korean DOS data:
1. load a real save,
2. walk in the saved port on the actual PORTMAP,
3. collide using the original PORTCHIP walk thresholds,
4. enter an actual ZA_DAT building door,
5. leave the building,
6. enter the Harbor,
7. sail out to the reconstructed WORLDMAP,
8. steer and move on the actual world chip map with coast collision.

This is an executable interactive slice, not yet a complete reimplementation of every game system.

## Korean save town coordinates
The user KOUKAI2.DAT has page size 33,340.
The active slot data base is page + 0x97.
Relative to that:
- +0x10 u16le = view X
- +0x12 u16le = view Y
- +0x14 u16le = player X in 23x23 view
- +0x16 u16le = player Y in 23x23 view

## Town collision
Each of the seven PORTCHIP sets has a 4-byte companion:
0: [0,29,34,40]
1: [0,21,26,31]
2: [0,20,25,30]
3: [0,22,26,31]
4: [0,37,42,48]
5: [0,32,37,46]
6: [0,21,22,27]

For a 2x2 player top-left at (x,y), use the two map tiles under the feet:
left = map[x,y+1], right = map[x+1,y+1]
blocked when:
- left >= b
- or a <= right < b
- or right >= c

Browser uses the equivalent positive condition:
left < b && (right < a || (right >= b && right < c)).

The runtime also implements:
- 23x23 saved viewport.
- four cardinal one-tile steps.
- side search around an obstacle up to 19 tiles.
- viewport scrolling to keep the player near the interior while preserving absolute map coordinates.
- building detection by exact ZA_DAT top-left coordinate.

## DOS port world table
The Korean DOS save carries a 130-record port table at page-relative 0x53BA.
Each 20-byte record is:
[nation byte][x u16le][y u16le][name 15 bytes].

Examples:
- Lisbon: (120,358)
- Seville: (142,372)
- Istanbul: (352,344)
- Tunis: (242,372)
- Danzig: (288,240)

Coordinates are world-chip coordinates.

## WORLDMAP + DATA1
User artifact:
- WORLDMAP.LZW: 3 LS11 chunks, sizes 25,394 / 21,973 / 23,907.
- DATA1.LZW: 19 chunks.
- DATA1[11] = 32,768 bytes; first 16,384 bytes are 128 planar 16x16 world tiles.
- DATA1[18] = 1,024 bytes = 256 x 4 cell-to-chip quad table.

WORLDMAP reconstruction:
- 1080x540 cells.
- chunks are 30 tile-column bands.
- 1350 tile records per chunk.
- each record expands a 12x12 cell tile using one of six templates selected by header 0x78..0x7D plus a 144-bit override mask.

Cell -> chip:
- value < 16: bits 3/2/1/0 map to LT/RT/LB/RB, set = land tile 0x41, clear = sea tile 0.
- value >= 16: DATA1[18][value*4..+3], values < 0x34 clamp to sea 0.
- final world = 2160x1080 chip positions.

Sailing collision:
- only chip IDs < 0x34 are passable; after normalization this is effectively sea chip 0.
- fleet occupies 2x2 chips; all four must be passable.

## Runtime controls
Town:
- arrows / WASD / num 8,6,2,4 = walk.
- walk onto a ZA_DAT door = enter building.
- Escape = leave building.

Harbor:
- Enter / 1 / S = sail.

Sea:
- Left / A / 4 = turn left.
- Right / D / 6 = turn right.
- Up / W / 8 / Space = move one world chip in heading, subject to 2x2 sea collision.
