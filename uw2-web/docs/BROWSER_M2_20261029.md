## Port map reconstruction
Artifact observations:
- PORTCHIP.LZW: LS11, 14 decompressed entries.
- Entries 0,2,4,6,8,10,12 are 30,720-byte graphics blocks.
- 30,720 = 16 * 3840 * 4 / 8 = 240 tiles * 16 * 16 * 4 / 8.
- Therefore 7 graphic banks, each 240 tiles at 16x16/4bpp.
- Odd entries are 4-byte companion records.
- PORTMAP.LZW: 101 entries; every entry is exactly 9,216 bytes = 96x96 byte tile map.
- All tile IDs in regular port maps 0..99 are <240.
- CHIP_NO.DAT: exactly 100 bytes; every value is 0..6.
- This establishes regular port ID -> CHIP_NO bank -> PORTMAP 96x96 -> PORTCHIP 240-tile bank.
- Current save slot 1: port 5, 튀니스, CHIP_NO[5]=2.
- Browser renders the full 1536x1536-pixel Tunis map at diagnostic scale.
- Runtime mini-view uses non-dominant-map-content centroid only until actual player coordinate offsets are proven; it is not claimed as player position.

## GRAPH family reconstruction
Independent evidence was cross-checked against the user's binaries:
- JohanLi/uncharted-waters-2-research documents GRAPH.DAT/GRAPH2.DAT/ENDGRP.DAT/OPGRAPH part record format.
- lychees/dol-k3-2 independently documents the same command stream.
- The earlier tentative interpretation of bytes 4..19 as palette data is corrected: they are eight u16 four-pixel pattern lookup values, not a palette.

User artifact record format:
- container: big-endian u32 offset table.
- record +0: width u16le.
- +2: height u16le.
- +4..19: eight u16le lookup values.
- +20: row-by-row command stream.
- 16-bit unit represents four planar pixels.
- 0x80 commands copy from previous units/rows.
- literal commands fill zero, lookup pattern, explicit 16-bit unit, or one-byte two-plane spread.

Full artifact validation:
- GRAPH.DAT: 65/65 records decoded.
- GRAPH2.DAT: 2/2.
- ENDGRP.DAT: 59/59.
- User OPGRAPH.LZW: LS11 14 parts, 108/108 GRAPH records.
- User OPGRAPH part record counts:
  16,2,2,11,8,8,8,8,15,11,5,2,2,10.
- The user's Korean artifact differs from public documentation that describes another 16-part/110-record release; runtime keeps artifact-derived 14/108 values.

REA decompile by file offset:
- OPEN.EXE file offset 0x0F7A -> screen GRAPH decoder.
  - verifies width 1..640, height 1..400.
  - screen stride 160 four-pixel units.
  - bit7 copy commands.
  - bit6 selects left-copy vs previous-row copy.
  - 8 lookup values loaded into table.
- OPEN.EXE file offset 0x13A2 -> memory GRAPH decoder.
  - verifies same command families and picture-width row stride.
This is direct shipped-binary confirmation of the JavaScript decoder.
